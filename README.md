# hxwl-06 显微镜玻片观察

样本、染色批次、观察记录与操作日志连成一条流程的多人观察工作台。

## 技术栈

React 19 + Vite + TypeScript + CSS。无后端，正式数据与未确认草稿分别存放在
浏览器 localStorage（跨同机多窗口通过 `storage` 事件实时同步，模拟共享库）。

## 本地运行

```bash
npm install
npm run dev      # 端口 5106
npm run build    # 类型与产物检查
```

## 业务规则（对应多窗口互相覆盖问题）

1. **批次版本乐观锁**：每个染色批次带 `version`。点“新增观察记录”进入编辑时锁定当时版本；
   点“确认保存”时用该版本与当前批次核对，不一致即判定冲突——本次保存**原样拒绝**，
   对方的染色备注与重点结构不会被覆盖，当前窗口弹出逐字段对照面板（你进入时 / 你的草稿 /
   对方保存后的新版本），由本人显式选择：
   - 以我的修改在新版本上重放（rebase）后再确认；
   - 采用对方新版本（自己的染色改动作废，观察内容保留）。
2. **观察记录只追加**：任何人的保存都是新增一条记录，旧记录不可改写。
3. **未确认草稿独立存放**：编辑内容自动保存到独立的草稿键（防抖约 0.4s）。
   浏览器关闭重开后，草稿只出现在“未确认草稿·非正式记录”待办区，标明所属批次、
   进入时版本（与当前版本不一致时红色提示）和最后编辑人；只有“确认保存”成功才转入正式列表，
   半成品不会出现在正式记录中。
4. **确认后可补录**：批次确认时冻结结论并推进版本，染色信息锁定；之后仍可补录观察记录，
   补录记录带“补录”标记，冻结结论与历史记录保持不变。旧版本窗口的补录同样被版本检查拦住。
5. **全量日志**：建批、保存观察、确认、补录均记录操作人、时间、动作与版本变迁，
   在“历史结论与操作日志”页可按人员、批次、动作筛选，按时间倒序查看。

## 多窗口手动复现

1. 开两个浏览器窗口（或两个标签页），分别在右上角输入不同操作人（如“甲同学”“乙同学”）。
2. 两人都对同一开放批次点“新增观察记录”（各自锁定同一版本）。
3. 乙先改染色备注并确认保存（版本推进）；甲再确认保存 → 甲的窗口出现冲突对照，乙的内容完好。
4. 在任一窗口输入到一半直接关浏览器，重开后内容只在“未确认草稿”区，且标明批次与版本。
5. 确认某批次后用“补录观察记录”追加，再到历史页按人员/时间追溯旧结论与全部操作。
