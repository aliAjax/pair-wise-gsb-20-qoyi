# hxwl-06 显微镜玻片观察

样本、染色批次、观察记录与操作日志一体化的多窗口录片流程。

## 技术栈

React 19 + Vite + TypeScript + 原生 CSS；本地持久化用 `localStorage`，
多窗口实时同步用 `BroadcastChannel` + `storage` 事件（无后端也能完整演示双人协作）。

## 本地运行

```bash
npm install
npm run dev      # http://localhost:5106
npm run build    # 类型检查 + 生产构建
```

## 流程与并发规则

数据链路：**样本 → 染色批次 → 观察记录（工作稿 / 正式结论 / 补录）→ 操作日志**。

### 1. 保存按进入编辑时的批次版本核对（乐观锁）

- 打开记录时锁定批次 `version` 并对四个字段（重点结构、染色备注、放大倍数、视野描述）留存基线快照。
- 保存时若批次版本已变（另一个窗口/另一个人先保存了），**保存被拦下，不覆盖任何字段**。
- 当前窗口弹出三方对照：`进入时的内容 / 我的修改 / 窗口外新版本`。
  - 双方改了同一字段且结果不同 → 硬冲突，必须人工二选一；
  - 只有一方改的字段自动合并（我没动的字段带入对方新值）；
  - 对照面板同时列出编辑期间窗口外的操作日志，标明新内容是谁、何时写的。
- 合并后以新版本重新提交；提交瞬间又被抢先则再次对照，杜绝“最后写入者覆盖”。

### 2. 草稿只恢复未确认的半成品

- 编辑中输入自动写入**草稿区**（与正式记录分开存储），关闭浏览器不丢。
- 重开后从「草稿箱」恢复，标明所属样本/批次、记录人、窗口、基于版本和保存时间。
- 草稿永远不与正式记录混排，并显式标注「未确认草稿 · 非正式」；保存成功即清除。
- 恢复时若批次版本已过期，直接进入对照；若批次已被确认，只能把内容转成补录。

### 3. 确认后只能补录，旧结论冻结

- 批次确认后工作稿转为只读正式结论（带确认时间），不可再编辑。
- 确认后仍可补录；补录只追加、不改旧结论，同样按进入补录时的版本核对（过期自动重定位后追加）。

### 4. 全程日志与历史可查

- 建立/保存记录、批次确认、补录均写入日志（时间、人员、窗口、批次、说明、版本）。
- 批次详情内有时间线：旧结论、补录、人员操作统一按时间排列。
- 「全部操作日志」页可按操作类型、人员、关键字筛选。

## 多窗口冲突演示

1. 开两个浏览器窗口（同一浏览器同一地址即可），各自选不同记录人。
2. A 窗口打开「碘液-20260929-A」里的记录并修改「染色备注」，先别保存。
3. B 窗口对同批次点「模拟另一窗口保存」（或直接编辑保存）。
4. 回 A 窗口点保存：被拦截并进入逐字段对照，选择后才能合并保存。
5. 关闭 A 窗口再重开：草稿箱中可恢复该半成品；对已确认批次操作则引导转补录。
